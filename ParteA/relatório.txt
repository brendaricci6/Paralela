Este código implementa um sistema de **histograma paralelo** em C, utilizando a biblioteca `pthread` para dividir o processamento entre vários núcleos da CPU. O objetivo é contar a frequência de números em determinados intervalos (bins) de forma otimizada.

Abaixo, explico cada função dividida por categorias:

---

## 1. Funções de Utilidade e Aleatoriedade

### `rand63` e `rand64`
Como a função padrão `rand()` geralmente retorna valores pequenos (até 32767 ou $2^{31}-1$), essas funções combinam vários resultados de `rand()` usando deslocamentos de bits (bit-shift) para gerar números aleatórios de 63 e 64 bits, respectivamente.
*   **`rand63`**: Gera um valor de 63 bits sem sinal.
*   **`rand64`**: Usa uma `union` para converter bits aleatórios diretamente em um `long long` (com sinal) de 64 bits.

### `ll_swap`
Uma função simples de troca (swap) que inverte os valores de duas variáveis do tipo `long long` usando um ponteiro temporário.

### `obter_tempo_atual`
Captura o tempo do sistema com precisão de nanossegundos usando `clock_gettime`. O cálculo `ts.tv_sec + ts.tv_nsec * 1e-9` converte tudo para um único valor em segundos (double).

### `limpar_cache`
Esta função tenta "limpar" a memória cache do processador. Ela percorre um buffer saltando de 64 em 64 bytes (o tamanho comum de uma linha de cache). O uso da palavra-chave `volatile` impede que o compilador ignore esse loop, garantindo que a leitura da memória realmente aconteça.

### `comparar_long_long`
Função de comparação padrão para ser usada com o `qsort` do C. Ela retorna -1, 1 ou 0 dependendo da relação entre dois números.

---

## 2. Geração de Dados e Definição de Intervalos

### `gen_test_data_balanced2`
Gera uma massa de dados de teste balanceada.
1.  Preenche o vetor com números sequenciais.
2.  Embaralha o vetor usando o algoritmo **Fisher-Yates**.
3.  Aplica um operador de módulo (`% nbins`) para garantir que os dados fiquem distribuídos uniformemente entre os bins.

### `build_limits_sp2_serial`
Define os "limites" de cada bin do histograma baseando-se nos dados de entrada:
1.  **Amostragem**: Seleciona alguns elementos do array original (`pivots`) de forma aleatória/saltada.
2.  **Ordenação**: Ordena esses pivôs.
3.  **Distribuição**: Define os limites dos bins baseando-se na posição desses pivôs ordenados.
4.  **Ajuste**: Garante que os limites sejam estritamente crescentes para evitar bins vazios ou sobrepostos.

---

## 3. Lógica do Histograma

### `find_bin` (O Coração da Busca)
Dado um valor `v`, esta função decide em qual bin ele deve entrar.
*   Primeiro, testa os extremos (se é menor que o primeiro ou maior que o último).
*   Se estiver no meio, utiliza **Busca Binária** para encontrar o bin correto em tempo logarítmico ($O(\log n)$), o que é muito mais rápido que testar bin por bin.

---

## 4. Gerenciamento de Threads (Thread Pool)

O código utiliza um modelo de **Thread Pool** com **Barreiras** para evitar o custo de criar e destruir threads a todo momento.

### `worker_run`
É a função que executa o trabalho real. Cada thread calcula qual fatia do array global (`start` até `end`) deve processar e preenche seu próprio histograma local (`hist_local`). Isso evita que várias threads tentem escrever no mesmo lugar ao mesmo tempo (o que causaria lentidão por contenção).

### `worker_thread`
O loop principal de cada thread escrava. Elas ficam paradas em uma **barreira** (`pthread_barrier_wait`). Quando o programa principal libera a barreira, elas acordam, verificam se há trabalho (`work_ready`), executam o `worker_run` e voltam a esperar na barreira.

### `pool_init` e `pool_destroy`
*   **Init**: Aloca memória para as threads, inicializa a barreira e cria as threads de fato.
*   **Destroy**: Sinaliza para as threads encerrarem (`shutdown_pool`), espera que terminem (`pthread_join`) e limpa a memória.

---

## 5. Execução e Validação

### `parallel_histogram`
É a função principal chamada pelo usuário.
1.  Se houver apenas 1 thread, ela executa de forma serial simples.
2.  Se houver múltiplas, ela configura os dados nas estruturas das threads.
3.  **Sinalização**: Ativa o `work_ready` e libera a barreira.
4.  **Colaboração**: A thread principal (ID 0) também ajuda no trabalho chamando `worker_run(0)`.
5.  **Redução**: Após todas terminarem, ela soma os resultados dos histogramas locais de cada thread no histograma global final.

### `verify_histogram`
Uma função de segurança que valida se o resultado paralelo está correto através de três estágios:
1.  **Estágio 1**: Compara o resultado paralelo com um resultado serial simples.
2.  **Estágio 2**: Faz uma contagem manual lenta usando um loop simples (`while`) para garantir que os limites foram respeitados.
3.  **Estágio 3**: Verifica se a soma de todos os bins é igual ao número total de elementos processados.

---

### Resumo do Fluxo
O código é um excelente exemplo de **computação paralela eficiente**: ele divide os dados, usa busca binária para classificação, evita conflitos de memória usando histogramas locais e gerencia as threads de forma performática com barreiras de sincronização.
